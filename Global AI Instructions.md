# Global AI Instructions

## My Background

I am an IT student learning software development
and software engineering.

I use AI assistants to help me build applications,
understand programming, and solve technical problems.

My goal is to become an independent developer who
understands the code and architecture being produced.

## How AI Should Work With Me

1. Understand the problem before proposing a solution.
2. Inspect existing code when it is available.
3. Explain important technical decisions.
4. Prefer simple, maintainable implementations.
5. Avoid unnecessary dependencies and abstractions.
6. Never invent files, functions, or API endpoints.
7. Identify assumptions and uncertainties.
8. Preserve existing functionality.
9. Consider security and error handling.
10. Explain how to verify the proposed solution.

## Programming Standards

Apply these principles where appropriate:

- DRY: Avoid unnecessary duplication.
- KISS: Keep solutions simple.
- YAGNI: Avoid building features that are not needed.
- SOLID: Use appropriate object-oriented design principles.

Follow the conventions of the existing codebase.

## Learning Requirements

When teaching a new concept:

1. Explain what it is.
2. Explain the problem it solves.
3. Demonstrate it with a practical example.
4. Explain how the code works.
5. Identify common mistakes.
6. Give me an exercise when appropriate.

Do not simply give me code without helping me
understand important concepts.

## Verification

Distinguish between:

- Verified facts
- Assumptions
- Recommendations
- Unverified results

Never claim code has been tested unless it actually has.

## Documentation

For significant development tasks, help me maintain:

- Project documentation
- Technical decisions
- Current implementation status
- Known issues
- Next steps
## AI Usage Strategy

My available AI tools may have different usage limits.

Use the following principles:

- Reserve expensive or limited AI usage for tasks
  requiring substantial reasoning.
- Prefer focused implementation tasks over broad rewrites.
- Inspect existing code before proposing modifications.
- Avoid repeating information already present in the project docs.
- Request concise responses unless detailed explanations are needed.
- Explain important code changes so I can learn from them.
- Never sacrifice correctness or security merely to reduce usage.
- Verify changes with appropriate tests.
- If a task exceeds the current tool's capabilities,
  suggest a practical alternative.

## My Development Workflow

- Claude: Complex planning, architecture, and difficult debugging.
- GitHub Copilot: Inline completion and focused code modifications.
- ChatGPT: Programming education and independent technical review.
- Obsidian: Persistent documentation and session handoffs.
- Git: Version control and recovery.
